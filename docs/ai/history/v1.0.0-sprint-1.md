# Sprint 1 (Foundation + Auth) Completion Summary

**Milestone:** Sprint 1 Completed
**Date:** September 27, 2026

## Overview

Sprint 1 laid the foundational database schema and authentication architecture for the CuyoTech University SSIS. All P0 requirements for this phase were fully implemented, tested, and merged into the `main` branch.

## Key Accomplishments

1. **Database Architecture (SETUP-1, SETUP-4):**
    - Created all 8 primary tables (`departments`, `users`, `students`, `courses`, `enrollments`, `payments`, `clearances`, `document_requests`, `audit_logs`).
    - Defined Eloquent models with strict `$fillable` arrays, casts, and relationships.
    - Enforced Single Table Inheritance (STI) for user roles via the `users.role` column, avoiding complex subtype models.

2. **Authentication & Security (FR-1, SETUP-3):**
    - Integrated **Laravel Sanctum** for API token-based authentication.
    - Configured CORS to securely communicate with the React frontend.
    - Implemented `POST /api/login` and `POST /api/logout` endpoints with robust Feature Tests.

3. **Global Middleware & Policies (SETUP-5, 6, 7):**
    - `CheckIsActive`: Global middleware that denies access (403) to deactivated accounts immediately.
    - `EnsureFreshRole`: Global middleware that fetches the user's role directly from the database to prevent stale token claims.
    - Role-based Policies (`StudentPolicy`, `RegistrarPolicy`, `CashierPolicy`, etc.) were wired into `AuthServiceProvider`.

4. **Financial Consistency (SETUP-2, FR-1.5):**
    - Established the strict money-handling convention: **All money is stored and calculated in integer centavos** to prevent floating-point precision loss. This is documented in `config/fees.php`.
    - Applied a strict `throttle:api` rate limit (60 requests per minute) across all API endpoints.

5. **Testing Infrastructure (SETUP-8, SETUP-9):**
    - Created factories and seeders for all entities to ensure clean, isolated testing and development environments.
    - Implemented passing Pest feature tests for all Auth workflows.

## Next Steps

Development proceeds to **Sprint 2**, focusing on the Student Portal, Registrar features (enrollment, grading), and Cashier features (payments, receipts).
